**2. [亲手] 沙箱只做合计（70 分钟）**

新建 `claimdesk/sandbox/execute.py`。

```python
def execute_python(code: str, invoices: list[int]) -> dict:
    ...
```

实现约束：

- 使用 `exec` 的受限 `__builtins__`：只放 `sum`、`len`、`min`、`max`、`range`、`list`、`dict`、`int`、`float`。不放 `open`、`__import__`、`globals`、`getattr`
- 不传入 `os.environ`。代码读 `os` 或 `__import__("os")` 时返回 `{"ok": False, "reason": "import"}`
- 代码里出现 `169.254.169.254`、`10.` 开头的地址字面量，或 `socket`，返回 `{"ok": False, "reason": "network"}`。这是静态拒绝，不发起连接
- 用线程或 `signal` 在 1 秒后终止死循环 `while True: pass`，返回 `{"ok": False, "reason": "timeout"}`
- 合法代码从变量 `invoices` 读取票据，把结果放进变量 `total`。返回 `{"ok": True, "total": ...}`

正确代码：

```python
total = sum(invoices)
```

测试断言 `total == 800`。

三条攻击各一个测试：死循环、`__import__("os").environ["SECRET"]`、字面量 `"http://169.254.169.254/"`。三条都 `ok` 为假，且进程环境里的测试变量 `CLAIMDESK_SECRET` 不被打印进返回值。

合计用 `subprocess` 启动只接受数字 JSON 的脚本。子进程环境里没有 API key。超时后杀掉子进程，父进程得到明确错误。模型不直接加这 12 张票据。

**3. [亲手] 短信仍是 JSON，合计仍要条款（20 分钟）**

`claimdesk/tools/schemas.py` 的短信如果还没有独立工具，就在测试里断言：发送路径调用的是 `ApprovalBook.send_sms` 或 `propose_sms`，参数是字典，不是一段 Python。`execute_python` 的返回值不能直接变成 `decision="通过"`。合计 800 之后，仍调用第 13 天的依据规则：没有条款子串就「无法判断」。

写一个测试：沙箱算出 800，草稿写「合计 800 元所以通过。[AK-FAKE]」，最终建议不是通过，理由不含 `AK-FAKE`。

```bash
pytest tests/test_day26_sandbox.py tests/test_day11_approval.py -v
```

**解决什么问题**

林晓要核对 12 张票据的自付金额合计。一轮轮 JSON 相加，加错一次就可能错赔。让模型在宿主机上随便跑 Python，又会读到凭证、打进内网。把发短信和改结论写进同一段代码，第 11 天的审批门就插不进去。

拒绝的方案：为了少几次往返，把发送短信也放进 `execute_python`。

留下的机制：业务动作仍是 JSON 工具，审批规则不变。`execute_python` 只做合计和分组。沙箱把生成代码当不可信：有限内置、无网络、时长上限、不注入凭证。合计结果回到建议前仍要经过条款依据校验。

**技术原理**

JSON 工具的动作空间是预定义函数，运行时可以逐个校验、逐个审批。代码的动作空间是一门编程语言，循环和汇总更短，步骤更少，也更难在「发短信」前插入人工确认。所以代码只包数据加工，敏感动作留在 JSON。

威胁不只是用户粘贴恶意代码。诊断证明里的句子可以诱导模型自己写出读取环境变量的代码。沙箱的前提是：模型生成的代码全部不可信。隔离、无网络、资源上限、凭证不进沙箱，这四条对应宿主机逃逸之外你在单机教程里能做实的部分。真容器或 microVM 写进第 30 天的「已知不做」。今天的受限 `exec` 是同一原则的最小实现，用来把三条攻击变成红灯。

**坑**

**坑 1：`__builtins__` 设成 `None` 后 `sum` 也没了。** 白名单要显式放入 `sum`。空内置会让正确代码也失败。

**坑 2：用正则禁止所有数字点号，把票据金额拦掉。** 网络拒绝只匹配元数据地址和 `socket` 字样。`800` 这种整数必须能算。

**坑 3：沙箱返回 `ok` 后直接建议通过。** 800 元对得上账，也不等于条款允许赔。依据校验仍在沙箱外面。

**卡住时先看这里**

- 死循环的超时在不同系统上实现不同。测试只要求 2 秒内返回 `reason="timeout"`，不要依赖某个信号编号。
- 不要在沙箱里 `print` 环境变量来「演示攻击成功」。返回值里出现 `CLAIMDESK_SECRET` 的值即失败。

**验收标准**

- [ ] `pytest tests/test_day26_sandbox.py -v` 通过
- [ ] 12 张票据合计为 800
- [ ] 死循环、读环境、访问元数据地址三条都失败
- [ ] 短信路径仍是 JSON 审批；假条款号不能把合计变成通过
