**1. [亲手] 入口按意图分流（30 分钟）**

`claimdesk/agent/desk.py` 的 `handle(world, request, model)`：

- `intent == "eligibility"`：调用 `run_intake`，返回 `RunResult`，`steps == 0`。不要把 `model` 传进会调用它的路径。0901 走这里。
- `intent == "investigate"`：不在这里调用 `run_agent`。只入队，1842 等 `drain_once()` 再跑循环。
- 其他意图：建议「无法判断」，`stop_reason="unknown"`。

`investigate` 不在请求线程里跑完。`POST /investigations` 向 `jobs` 插入 `id`、`claim_id`、`status=accepted`、`intent`，响应只有 `job_id`，此时模型还没被调用。测试调用 `drain_once()` 后再断言 1842 的工具顺序。`eligibility` 不插入 `jobs`。

**2. [亲手] 循环里带着计划（70 分钟）**

`claimdesk/agent/loop.py` 的 `run_agent`。`Task` 至少包含：

- `claim_id`
- `product`，来自案件，固定「安康住院2024」
- `plan`，原文包含「计划」二字，测试断言每一轮 prompt 都含「计划」
- `goal`

模型返回三种动作之一：

- `{"type": "tool", "name": "...", "args": {...}}`
- `{"type": "final", "decision": "...", "clause_ids": [...]}`

1842 的桩按这个顺序回答，你的循环要照做并留下 trace：

1. `get_claim_history`，参数 `{"policy_no": "POL-1842"}`
2. `search_clauses`，参数 `{"query": "等待期 既往住院"}`
3. `final`，决策「复核」，条款 `AK-2024-3.1`

历史工具要能在轨迹文本里出现 `CLM-2026-1831`（周启明在 POL-ZHOU-2 上的门诊案）。`format_trace()` 把每步拼成 `工具名: 文本`。

工具结果写回观察列表后，下一轮 prompt 能看见它。模型因此可以改检索词。这就是规划、知识和工具通过上下文闭环。

**4. [AI] 可以生成循环骨架，不能生成图**

提示词写明：不要 import langgraph；不要让 eligibility 进入循环；计划字符串由你指定。生成后自己走一遍三步桩，确认 trace 顺序。

**解决什么问题**

周衡问 1842：先查去年有没有类似住院，再决定条款怎么套。分支已经写不完。若把第 3 天就能判定的 0901 也拖进循环，每天上百次的资格问题会开始烧token。

拒绝的方案：所有请求都进 Agent。今天就上 LangGraph。也不在 HTTP 请求里同步跑完循环。

留下的机制：手写循环只接开放协查。模型先调历史案件，再自己决定检索词。资格问题仍然零步、零模型。

**技术原理**

规划是控制中枢：先决定需要什么信息。知识来自工具返回，而不是只来自参数记忆。工具既是动作也是感知。三者的接口是上下文：计划要写进每一轮 prompt，工具结果要结构化地写回去，下一轮才能改计划。

这是 Agentic RAG 的最小形态。检索不再是写死的一次，模型决定检索词。代价是多轮调用。所以分流放在 `handle`：能穷举的路径保持第 3、4 天的形态。

图运行时适合有共享状态、并行和人工中断的争议合并。那是第 19 天。今天的循环是一个 for 加一份观察列表，足够讲清闭环。

**坑**

**坑 1：资格路径把 model 传给了 `run_intake`，而你又在规则前「问一句模型」。** 测试的桩会炸。eligibility 分支不要调用 `model`。

**坑 2：历史和检索的顺序写反。** 先检索再查历史，测试的 `index` 断言失败。开放协查的第一跳是历史，检索词依赖这一跳。

**坑 3：计划只写在系统注释里，没有放进 prompt。** `all("计划" in prompt for prompt in prompts)` 会失败。`render_context` 的头部要带计划。

**卡住时先看这里**

- 历史案件的实现在 `claimdesk/tools/schemas.py` 的 `get_claim_history`。保单号 `POL-1842` 对应被保险人周启明，相关案件列表里有 `CLM-2026-1831`。
- `RunResult.trace` 的元素含 `tool` 键。`format_trace` 用这个列表。

**验收标准**
