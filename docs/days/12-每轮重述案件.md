**今日产出**

每一轮 prompt 重述案件号、产品和计划。旧观察收成摘要，最近两轮保留原文并截断。模型即使把产品答成车险、把案件号答成别的，对外结果仍绑定 CLM-2026-1842 和安康住院2024。单轮上下文字数有硬上限。事实写进 `memory` 表；推断写入会被拒绝。查询必须带 `tenant_id=anlan-chengdu`。


标了 **[亲手]** 的自己写。标了 **[AI]** 的，你先把约束写清楚再生成：保留几轮、截断长度、绑定字段不要让它改。生成之后用 pytest 验收。

**1. [亲手] 事实侧车与长期记忆接口（20 分钟）**

`claimdesk/agent/memory.py`：

- `EntitySidecar` 固定字段：`claim_id`、`product`、`policy_no`、`clause_version`（来自 Task/env，**不参与摘要**）。
- `remember_fact(claim_id, key, value)` 只存可验证事实；`infer_*` 字段不得写入长期记忆。
- `render_context` 头部必须从 Sidecar 注入上述字段。

`remember_fact` 写入 SQLite `memory`。只接受案件号、产品、保单号、条款版本。带推断标记的写入直接拒绝。`render_context` 的头部从这张表读，不从模型输出读产品名。读写都带 `tenant_id=anlan-chengdu`，缺租户的查询失败。

**2. [亲手] 写上下文渲染（40 分钟）**

`claimdesk/agent/context.py`：

- `MAX_CONTEXT_CHARS = 1800`
- `MAX_OBS = 160`
- `render_context(task, observations)` 的头部四行：案件、产品、计划、目标。计划字符串里含「计划」，与第 8 天的断言兼容
- 观察超过 2 条时，更早的只留工具名摘要，文本以「较早观察摘要:」开头；最后两条保留，每条正文截到 160 字
- 拼出来的整段长度不超过 1800。头部优先，正文从尾部截

**3. [亲手] 绑定层不听模型的产品字段（30 分钟）**

`run_agent` 在 `final` 时，`RunResult.claim_id` 和 `product` 取自 `Task`，不取自模型返回的 `claim_id` / `product`。理由字符串使用任务上的案件号和产品。模型返回的「车险」不得出现在 `suggestion.rationale`。

测试会跑 15 次 `echo` 工具，参数里带很长的「费用明细」，并在第 1 步埋下 `UNIQUE_OLD`，第 14 步起埋下 `UNIQUE_NEW`。第 16 次模型调用时断言：

- prompt 含 `CLM-2026-1842` 和 `安康住院2024`
- prompt 含 `UNIQUE_NEW`
- prompt 不含 `UNIQUE_OLD`
- `len(prompt) <= MAX_CONTEXT_CHARS`

然后模型返回 `decision="通过"`，`product="车险"`，`claim_id="CLM-CAR"`。结果仍是 1842 与安康住院2024。

这次运行把预算放到 `Budget(max_steps=20, max_tokens=200000)`，否则第 10 天的默认 8 步会提前停。

**解决什么问题**

林晓追问费用和医院，后来突然问划痕。助手如果顺着这句话走，就会把住院医疗核成车险。把 15 轮工具原文全塞进下一次提示，既会漂，也会让每一轮都为同一大段观察付费。

拒绝的方案：靠模型记住案件号。把全部工具原文留在上下文里。事实放在 `memory` 表，推断不能写入。

留下的机制：每轮固定重述案件号、产品和计划。旧观察只留摘要，最近两轮保留并截断。绑定层维持 CLM-2026-1842 和安康住院2024。

**技术原理**

上下文是规划、知识和工具的接口。计划不每轮重述，几轮之后模型只看见最近的划痕。工具返回不截断，一次查询的长 JSON 会在后续每一步被重复计费。这就是费用归因里「单步膨胀」的来源，第 22 天会用账单把这件事算出来。今天先把长度上限和摘要做进渲染函数。

绑定层是代码，不是提示词。模型可以在 `final` 里填写任何产品名，对外字段以任务对象为准。专员看到的建议头不会变成车险。

**坑**

**坑 1：摘要把最近两轮也压掉了。** 测试要求 `UNIQUE_NEW` 还在、`UNIQUE_OLD` 不在。切分点是 `observations[:-2]` 与最后两条。

**坑 2：截断只截工具返回，不截拼好的 prompt。** 15 轮之后头部加正文仍可能超过 1800。渲染函数最后要保证总长度。

**坑 3：`final` 采用了模型给的 `product`。** `result.product` 必须来自案件。理由里出现「车险」即失败。

**卡住时先看这里**

- echo 工具由测试注入，不在默认工具表里。`run_agent(..., tools={"echo": ...})` 要覆盖或并入默认表。
- 第 1 步的标记在 15 轮之后应只出现在摘要的工具名里，不能把整段 `UNIQUE_OLD` 正文留住。摘要用工具名列表，不要用观察全文。

**验收标准**

- [ ] `pytest tests/test_day12_context.py -v` 通过
- [ ] 长对话后 `claim_id` 仍是 CLM-2026-1842，产品仍是安康住院2024
- [ ] prompt 长度不超过 `MAX_CONTEXT_CHARS`
- [ ] 第 8 天「每轮 prompt 含计划」仍然通过
