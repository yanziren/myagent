**解决什么问题**

限额表曾被从中切开。林晓用客户原话「等了多久才能报」，召回是空的。她不会先把口语改成「等待期」。为了一条例去建知识图谱，或把口语失败升级成 Agent，都超过了今天的证据。混合检索因此保持为纯函数。

拒绝的方案：今天引入 GraphRAG 或自主检索。也不把低分检索自动入队。

留下的机制：条款按条、款、表整块切分。检索是 BM25 加向量式的字面重叠。问句先做确定性的术语归一。周启明的跨保单问题留到后面用关系解决。

**技术原理**

切分决定召回上限。表格、条款的但书、例外句，要和它所属的那一条待在一起。固定长度切分在第 6 天已经证明会制造「生成幻觉」：模型只看见半句「不赔」。

查询侧的措辞差，可以用一张术语表解决，不必把决策权交给模型。术语表是 Workflow：输入输出确定，测试可以锁住「等了多久才能报」一定变成等待期。

混合检索补的是字面和语义各漏一边的情况。它仍然是一次调用。Agentic RAG 的「要不要再查」留到下一周，而且只对开放协查开放。

**坑**

**坑 1：标题切分把表格拆成单独的行块。** 现象：床位费 300/日 找不到年限额那一行的上下文。修法：`##` 之间的全部正文，包括表格，属于同一块。

**坑 2：术语表做成了模型调用。** 现象：改写不稳定，测试时而命中时而命中别的节。修法：字典查找，未登录的口语原样进入检索。

**坑 3：顺手把跨保单问题用更长的 CLAUSE 文本「包含周启明」修绿。** 条款里没有周启明。把他写进条款是污染知识库。失败样本保持失败。

**卡住时先看这里**

- `pip install -e .` 会装上 `rank-bm25`。没装时 hybrid 的导入会失败。
- 中文 BM25 需要先分词。可以用字或二元组当 token，和 `_bigram_score` 对齐，避免今天引入分词器。
