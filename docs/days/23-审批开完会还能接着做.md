**1. [亲手] 三段式短信日志（40 分钟）**

新建 `claimdesk/traces/resume.py`。

`SmsLog` 记录三条，键是幂等键 `idem`：

- `intent`：准备发给谁、正文、案件号
- `result`：`sent` 或缺失
- 外部探针 `already_sent(idem) -> bool`，由测试注入

`resume_send(log, idem, send_fn, already_sent)`：

- 已有 `result == "sent"` → 不再调用 `send_fn`
- 有 `intent` 但没有 `result`，且 `already_sent` 为真 → 补记 `result`，不再发送
- 有 `intent` 但没有 `result`，且外部也没有 → 调用一次 `send_fn`，再记 `result`
- 没有 `intent` → 不发送

测试用一个计数器当 `send_fn`。场景：先 `intent`，调用一次发送成功但在写 `result` 前「进程死了」（你直接构造只有 intent 的日志，并让 `already_sent` 返回真）。恢复后计数器仍是 0。另一场景 `already_sent` 为假，恢复后计数器是 1，再恢复一次仍然是 1。

恢复时新开一条 SQLite 连接。已是 `idempotency.status=done` 的短信不再发送。`checkpoints` 存 `job_id`、步骤号和已完成副作用的键。`blocked` 任务跳过这些键继续。不要把整段聊天记录当检查点。

**2. [亲手] 恢复的上下文是结构化状态（25 分钟）**

`restore(checkpoint) -> dict` 只复制这些键：`goal`、`plan`、`done`、`recent`。测试放入一个 10000 字的 `full_history`，断言它不在返回值里。

`reconcile(plan, observed_waiting_days, checkpoint_waiting_days) -> str`：两者相同则返回原计划；不同则返回新字符串，且包含「重新观察」和观察到的天数。用 V3 的 30 对上检查点里的 30，计划不变。检查点写 30、外部已是 V4 的 90，计划必须变。

```bash
pytest tests/test_day23_resume.py tests/test_day11_approval.py -v
```

第 11 天的未批准不发送仍然要绿。恢复不能绕过 `ApprovalBook`。

**解决什么问题**

周衡批到一半去开会，进程重启。恢复后补件短信发了两次。若把中断前的全部历史原样灌回，上下文回到第 12 天以前的膨胀。若对「有意图无结果」盲目再执行，客户会收到两条补件短信。

拒绝的方案：恢复时不核对外部世界。把全部聊天记录塞回 prompt。检查点是表里的步骤和已完成副作用，不是全文。

留下的机制：事件日志加检查点。恢复时载入目标、计划、已完成清单和近期消息。写操作使用幂等键，顺序是先记意图、再执行、后记结果。恢复时对「有意图无结果」先查外部是否已发送。保单状态与检查点不一致就改计划。

**技术原理**

中断可能落在「工具已执行、结果还没写入」的缝里。幂等键让第二次执行变成查询。三段式把这个缝变成可判定的状态，而不是靠模型记得自己发过没有。

恢复也是一次压缩。长任务死在后半段时，全量历史正是最贵的那段。结构化状态加上近期消息，等于借重启做了第 12 天的摘要。环境会漂移：条款版本、保单状态、材料是否补齐，都可能在开会的两小时里变了。先重新观察，再沿用计划。

检查点同时服务第 19 天的人工中断和第 20 天的回放。今天补上的是副作用的那一截。

**坑**

**坑 1：`already_sent` 为真时仍调用 `send_fn` 以求「确认」。** 计数器会变成 1。外部已发送就只补记结果。

**坑 2：`restore` 把 `full_history` 一并返回。** 测试专门放了一段长文。白名单键，不要 `checkpoint.copy()`。

**坑 3：等待期从 30 变成 90 仍返回旧计划。** `reconcile` 用整数比较。相等才沿用。

**卡住时先看这里**

- 幂等键用字符串，测试用 `"sms-1842-1"`。不要用Python对象的 `id()`。
- 审批单的 `pending` 在重启后要从 `ApprovalBook` 的可序列化字段恢复。今天的测试可以只覆盖短信日志；审批单若还只活在内存里，在笔记里写明第 23 天的日志是发送路径的真相来源。

**验收标准**

- [ ] `pytest tests/test_day23_resume.py -v` 通过
- [ ] 外部已发送时，恢复不再调用发送函数
- [ ] 外部未发送时只发送一次，第二次恢复不再发送
- [ ] 恢复结果不含全量历史；等待期 30 与 90 不一致时计划被改写
