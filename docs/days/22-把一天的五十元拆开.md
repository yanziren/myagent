**3. [亲手] 软预算、硬预算、无进展挂起（25 分钟）**

`claimdesk/billing/budget.py`：

```python
def gate(spent: float, soft: float = 50.0, hard: float = 80.0, no_progress: bool = False) -> str:
    ...
```

- `spent < soft` 且没有无进展 → `run`
- `soft <= spent < hard` → `converge`（停止探索，用已有证据作答）
- `spent >= hard` 或 `no_progress` → `suspend`

**解决什么问题**

一个争议案挂着没人看，一天的接口费用被它打穿。何岚要的是哪一段时间、哪一种结构、上下文里的哪一块。没有每步 token 记录，事后只能猜。

拒绝的方案：只设一个总步数，不看成本和进展。

留下的机制：按时间、按步数乘单步 token、按上下文构成、按行为回放做归因。单案软预算告警并停止探索，硬预算停止。连续若干步没有新证据就挂起。

**技术原理**

费用等于步数乘每步 token。长任务最常见的是单步膨胀：工具返回和完整历史留在上下文里，之后每一步都为它们付费。第 12 天的截断和摘要就是为了压 `piece="history"`。今天用录像证明，不截断时历史会占到七成以上。

另一类是步数爆炸，第 10 天的指纹和步数帽负责。预算门和它们互补：步数不多、单步极大时，步数帽还没到，钱已经没了。

无进展检测看的是「最近几步有没有新证据」，不是看模型自述「我在努力」。挂起等人，比烧完硬预算再停便宜。

**坑**

**坑 1：用总金额一个数写笔记。** 何岚无法决定改截断还是改重试。笔记必须点名「历史全文」和「第 3 步之后」。

**坑 2：软预算到达后仍允许新的工具调用。** `converge` 的含义是不再探索。测试可以断言闸门返回值，调用方在第 25 天以前只要不在 `converge` 之后再发 `get_claim_history`。

**坑 3：无进展被硬预算挡住才停。** `no_progress=True` 即使只花了 10 元也要 `suspend`。进展和金额是两道闸。

**卡住时先看这里**

- 单价 0.0001 只为测试心算。真实供应商价格换算放在配置里，不要写死在归因句子中。
- `docs/billing-note.md` 用 UTF-8。测试按子串查找「历史全文」和「第 3 步」。
