**1. [亲手] 实现 `answer_grounded`（60 分钟）**

`claimdesk/rag/ground.py`：

```python
def answer_grounded(question: str, draft: str) -> Suggestion:
    ...
```

步骤：

1. 用 `chunk_by_heading(CLAUSE_V3)` 得到按标题切开的条款。
2. 用 `_bigram_score` 取和问题最相似的一块。分数 `<= 0` 时直接返回 `decision="无法判断"`，条款空，理由「资料不足，缺少可引用条款。」不要阅读 draft。
3. 用正则 `([^\[\]]+?)\[(AK-[^\]]+)\]` 从 draft 抽出「句子 + 条款号」。
4. 句子 `strip(" 。，")` 之后，必须是该条款号对应正文的子串。条款号不存在，或句子不在正文里，丢掉。
5. 一句都留不下：同样返回无法判断，理由同上。留下的句子用「。」拼进 `rationale`，条款号按保留顺序放入 `clause_ids`。决策用「答复」，测试只要求它不是「无法判断」。

忠实度在这批用例上是：留下的句子数 / draft 里的引用句数。今天用三条测试锁住两端，第 28 天再按这个定义做切片。

对不上的句子删掉后，结论放在建议的 `decision` 里，形状和第 3 天的 JSON 相同。今天不新建一张无法判断表。

**解决什么问题**

条款写等待期 30 日。草稿却说行业惯例是 90 天，还标了一个不存在的条款号。专员差点按 90 天拒赔。提示词里写「根据资料回答」挡不住补全、空检索硬答和过度推断。无法判断作为建议字段返回，不另建表。

拒绝的方案：把忠实度押在一句指令上。无法判断是返回字段，不是新表。

留下的机制：检索分数不够就拒答。每句必须带真实条款号，而且原句要能在该条款里找到。对不上的句子删掉，结论降为无法判断。

**技术原理**

「只根据检索内容回答」能降低幻觉率，挡不住三种失效：资料只沾边时用参数记忆补缝、检索为空仍硬答、把「可能相关」说成因果。所以校验放在程序里。引用格式强迫每个论断锚到一个编号，编造的成本变成「这句必须是原文子串」。

子串检查会漏掉同义改写的正确句子，也会放过断章取义但原文确实有这几个字的句子。它是便宜、稳定的第一层。第 89 题的 faithfulness 是把答案拆成原子论断再逐条核对。今天的删句就是这个指标的可执行版本。answer relevance（答非所问）留到低分拒答：问题与条款完全无重叠时，不评价草稿写得漂不漂亮。

**坑**

**坑 1：句子带上了句号，子串对不上。** 条款里是「自投保日起 30 日内为等待期。」草稿在括号前还有句号。`strip(" 。，")` 再比较。

**坑 2：假条款号被忽略后，句子仍输出。** 没有对应正文就是丢掉整句，不能只删编号、保留「90 天」。

**坑 3：低分问题仍返回草稿，只是决策改成无法判断，理由里却留下「行业惯例」。** 低分分支不要拼接 draft。

**卡住时先看这里**

- AK-2024-3.1 的正文以「自投保日起 30 日内为等待期」开头。草稿必须用这句，不能用「等待期为三十天」这种改写，否则子串失败，整题变成无法判断。
- `AK-FAKE` 不在 `chunk_by_heading` 的索引里，`index.get` 得到空字符串。
