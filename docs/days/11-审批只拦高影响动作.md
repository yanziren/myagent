**1. [亲手] 三档动作（40 分钟）**

`claimdesk/guards/approval.py` 的 `ApprovalBook`：

- `save_draft`：立刻 `status="audited"`，正文进入 `audit`。不打断查询。
- `propose_sms`：`status="pending"`，动作名 `send_sms`。字段含收件人、正文、理由、金额、案件号。
- `send_sms`：审批单不存在、未批准、或动作不是 `send_sms` 时抛 `ApprovalRequired`。未批准调用时 `sent` 仍为空。
- `reject`：状态改为 `rejected`，不写入 `sent`。
- `edit`：只允许改 `pending` 的正文。
- `approve`：`send_sms` 被批准后，正文进入 `sent`。
- `finalize(claim_id, amount)`：金额 18600 时返回仍为 `pending` 的票据，`core_writes` 保持空列表。超过 5000 的写核心停在复核，不落库。

`approval_view(ticket)` 的键至少包含 `recipient`、`body`、`reason`、`amount`。周衡要在十几秒内看完影响面。

高影响动作把对应 `jobs.status` 写成 `blocked`，并追加 `audit`。审计列只有 `action`、`amount`、`target`、`approver`。短信措辞可以出现在草稿正文里，但不能作为通过条件。没有审批行时发送失败。周衡点头是新的一行审计，然后才离开 `blocked`。

**2. [亲手] 走一遍林晓的短信（20 分钟）**

林晓要发的初稿是「您已被拒赔」。这句像拒赔结论，赵琪会接到投诉。

顺序：

1. `send_sms(None, ...)` 抛 `ApprovalRequired`
2. `propose_sms(..., body="您已被拒赔", amount=18600, claim_id="CLM-2026-1842")`
3. `reject` 后 `sent == []`
4. 另一张单：`edit` 成「请补充诊断证明，此为补件不是拒赔」，再 `approve`，`sent` 里只有改后的正文

**3. [亲手] 审批查询接口**

`claimdesk/app/http_api.py` 的 `post_json("/approvals", {"ticket_id": ...}, book)` 返回金额 18600，正文含「请补充诊断证明」。这是给周衡的决策上下文，不是第二个会自动发送的通道。

```bash
pytest tests/test_day11_approval.py -v
```

进程重启后的恢复留到第 23 天。今天只保证未批准则动作不发生。

**解决什么问题**

林晓让助手把补件短信发出去。正文写得像已经拒赔，客户投诉到赵琪。1842 的金额是 18600，超过 5000。若只读助手里直接调用发送，覆水难收。若每一条查询都拿去审批，周衡会开始无脑点通过。

拒绝的方案：只读路径上直接发送。用对话里的「用户同意了」代替审批。点头必须是 `audit` 行，不是提示词。

留下的机制：只读放开，草稿只审计，短信和提交必须周衡批准。拒绝不会发出。草稿可以改完再批。高金额不能写进核心系统。

**技术原理**

有界自主按「风险乘可逆性」分档。只读没有副作用。草稿可改、可丢。短信代表公司对外说话，不可逆。写核心系统在金额超过 5000 时同样不可逆。档位看动作、金额和对象，不看对话里有没有「已经同意」。第 14 天会把这一点做成不读对话的函数签名。

审批点过密会造成审批疲劳。查询不进这个队列。人的注意力留给短信措辞和 18600 的写核心。

挂起和恢复需要检查点。今天的 `pending` 票据就是以后恢复的那张单。第 23 天补上「先记意图、再执行、后记结果」，避免重启后发两次。

**坑**

**坑 1：`edit` 发生在 `approve` 之后仍能改正文。** 已批准的单不允许再改。测试只在 `pending` 时编辑。

**坑 2：`reject` 之后 `sent` 里留下了初稿。** 拒绝的定义就是一条都不发。`sent` 只在 `approve` 且动作为 `send_sms` 时追加。

**坑 3：`finalize` 把 18600 写进 `core_writes`。** 高金额停在 `pending`。核心写入列表保持空。

**卡住时先看这里**

- 异常类型是 `ApprovalRequired`，继承 `PermissionError`。测试用 `pytest.raises(ApprovalRequired)`。
- 票据 id 形如 `APR-1`。测试不依赖具体序号，依赖状态和 `sent` 的内容。

**验收标准**

- [ ] `pytest tests/test_day11_approval.py -v` 通过
- [ ] 未批准或被拒绝时 `sent` 为空
- [ ] 批准发出的是改后的补件措辞
- [ ] 18600 的 `finalize` 不产生核心写入
- [ ] 草稿进入 `audit`，且不要求审批
