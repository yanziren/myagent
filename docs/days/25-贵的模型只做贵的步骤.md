**2. [亲手] 费用按路径记账（25 分钟）**

`charge(path, tokens, price)` 把金额加进 `ledger[path]`。价格表：`small` 每 token 0.00002 元，`large` 每 token 0.0001 元，`none` 为 0。

造一天的账：100 次资格走 `none`，50 次摘要走 `small` 各 200 token，2 次争议拆解走 `large` 各 2000 token。断言 `ledger["large"]` 大于 `ledger["small"]` 的这种结构不必成立，你按上面的数算清楚并写进测试。必须断言：

- `ledger["none"] == 0`
- `ledger` 的键彼此独立，摘要的钱不会加进 `large`
- 总和小于 50 元

这就是客服漏斗在核赔台的形态：大多数请求停在规则，旗舰模型只碰到争议拆解。

```bash
pytest tests/test_day25_routing.py tests/test_day03_rules.py -v
```

**解决什么问题**

日费用撞上 50 元。资格解释、摘要和参数抽取也在走旗舰模型。若把争议案直接丢给小模型且没有退路，2208 的冲突又会被写成一句「通过」。

拒绝的方案：用一个固定模型名跑完整条链路。调用必须经过模型网关。

留下的机制：规则处理确定的头尾。同一争议案里，拆解走大模型，摘要和抽取走小模型。低置信升级。用户说没听懂时，这一会话后续步骤升级。费用按路径分开。

**技术原理**

生产流量里大部分请求是简单的。路由错了，质量会在某一个场景翻车，所以要有退路：置信度不够就升级，用户明确不满就升级。核赔台的路由还有一步是「不调用模型」。资格和缺材料在第 3、4 天已经是规则和流水线，它们的路径价格是 0。

按步骤路由比按整单路由省得更细。一张争议案里，拆解需要强模型，把医学意见压成摘要不需要。报表必须按路径切片。只看一天 50 元的总数，无法知道是摘要走错了档，还是争议案本身变多了。

模型价格会变。阈值 0.8 和两档单价放在函数参数的默认值里，测试锁定默认行为，以后调价只改变量。

**坑**

**坑 1：`eligibility` 返回 `small`。** 第 3 天的测试要求零次调用。路由返回 `none`，调用方看到 `none` 就不要构造模型请求。

**坑 2：投诉只影响当前这一步，下一步又回到小模型。** `complained` 由会话传入，后续 `summarize` 和 `extract` 都看这个标志。测试连续调用两次摘要，两次都是 `large`。

**坑 3：账本用一个浮点总数。** 必须保留路径键。总和可以用路径相加得到。

**卡住时先看这里**

- 置信度缺省时，`summarize` 按低置信处理，返回 `large`。不要默认 1.0。
- 单价是教学值。50 元软顶沿用第 22 天的 `gate`。今天先保证这一天的样例账低于软顶。
