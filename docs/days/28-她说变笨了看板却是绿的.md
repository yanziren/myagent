**今日产出**

林晓的反馈带着会话编号。你能把她的 trace 和两周前的同类会话对齐，并说明看板 92% 为什么没动：复杂案被简单案摊平了。固定探针在模型 id 变化时告警。这几条会话按召回、精度、忠实度、是否答非所问拆开。探针是一组固定 job 输入。仪表按 `intent` 切片。资格全绿时，协查切片仍可以是红的。

**1. [亲手] 反馈必须带会话（20 分钟）**

新建 `claimdesk/observe/feedback.py`。

`Feedback` 缺 `trace_id` 时 `accept` 抛 `ValueError`。测试传入「变笨了」但没有编号，断言抛错。带上 `tr-15` 才入库。

**2. [亲手] 把 92% 切开（25 分钟）**

`slice_success(rows) -> dict`。每行有 `difficulty`（`easy` 或 `hard`）和 `ok`。

造 100 行：90 行 easy 且 ok，2 行 hard 且 ok，8 行 hard 且失败。全局成功率是 0.92。`by_difficulty["hard"]` 是 0.2。测试同时断言这两个数。笔记 `docs/dumber-note.md` 写明盲区是切片，并提到全局 92% 与复杂案 20%。

探针是测试里写死的两组 `jobs` 输入，`intent` 分别是资格和开放协查。仪表按 `intent` 查询。资格全部成功、协查全部失败时，总成功率仍然高，协查切片是失败。不要只返回一个全局百分比。

**3. [亲手] 探针与四个 RAG 维度（30 分钟）**

`claimdesk/observe/probes.py`。

探针输入固定为「等待期是多少天」，期望条款 `AK-2024-3.1`，期望正文含「30」（V3）。`run_probe(model_id, answer_fn)` 在 `model_id` 与上次不同，或答案不含「30」时，`alert` 为真。测试先跑 `claim-model-2026-10-01`，再跑 `claim-model-2026-10-18`，第二次必须告警。

对林晓的三条坏会话调用一个纯函数 `rag_dims(case) -> dict`，字段为：

- `recall`：应召回的条款是否出现在上下文
- `precision`：上下文里无关条款的比例是否过高（测试用「无关块数量 > 相关块」表示低精度）
- `faithfulness`：复用第 13 天，理由里的句子是否是条款子串
- `relevance`：问题含「等待期」而回答只谈「床位费」时为假

三条用例分别打掉一个维度，第四个字段保持为真。测试断言被打掉的那个字段为假，避免一个「答错了」含混过去。

```bash
pytest tests/test_day28_observe.py tests/test_day13_grounding.py -v
```

**解决什么问题**

林晓说助手变笨了。看板成功率仍是 92%。若先把反馈当成错觉，复杂案上的退步会一直被简单资格题的通过数盖住。

拒绝的方案：只看全局均值。没有会话编号也收下「变笨了」三个字。

留下的机制：反馈带 trace。成功率按难度切开。固定探针输入不变，专门抓模型 id 变化。坏会话按召回、精度、忠实度、是否答非所问拆开。

**技术原理**

用户体验和指标体系不一致时，先怀疑指标有盲区。常见盲区是切片被稀释、成功的定义太松、评估集还是旧分布。今天的 90 道简单题对 10 道难题，就是稀释。第 20 天的 trace 让你能对比两周前的工具返回和模型 id，而不是再问模型「你当时为什么变笨」。

静默退化不抛异常。固定探针把输入钉死，输出变化就只可能来自系统本身：模型被换了、条款指针被拨了、提示词被改了。第 27 天的日期版本和这里的告警是同一件事的两侧。

RAG 的四个维度用来把「变笨」变成工单。召回低去看切分和查询，精度低去看排序，忠实度低去看第 13 天的删句，相关性低去看问句是否跑偏。第 6 天的纪律仍然有效：先看召回里有没有那句话。

**坑**

**坑 1：全局 0.92 被写成唯一断言。** 难题成功率 0.2 必须同时出现。否则测试和看板犯同一个错。

**坑 2：探针用当天的随机问句。** 输入一变，告警就无法归因。问句常量写在模块里。

**坑 3：四个维度合成一个分数。** 测试要能指出是哪一个字段为假。合成分数会把召回问题说成忠实度问题。

**卡住时先看这里**

- 0.92 的算法：92 条 ok / 100。hard 的 0.2 是 2/10。两边都写进测试，防止手算改分母。
- 探针比较模型 id 用字符串相等。`latest` 和日期版本永远不相等，会每轮告警。这也是拒绝 `latest` 的一个理由。
